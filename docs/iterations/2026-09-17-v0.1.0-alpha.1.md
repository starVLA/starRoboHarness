# v0.1.0-alpha.1 development snapshot

Date: 2026-09-17

Status: collaborative alpha; experimental rollout API; no formal benchmark
result

## Purpose

This snapshot hands the first integrated UnityPolicy implementation to multiple
contributors. It records the code and evidence boundary so future changes can
be reviewed without reconstructing decisions from terminal logs or private
sessions.

The target comparison is QwenPI_v3, GPT-6 Astra + QwenPI_v3, and GPT-6 Astra
Direct on the same five RoboDojo tasks, five fixed cases per task. That formal
campaign requires 75 valid native terminal episodes. It had not started when
this snapshot was prepared.

## What changed since the public main branch

### Runtime and method contracts

- Added explicit lifetime, process, interruption, native-terminal, and result
  validity semantics.
- Bridged QwenPI_v3 proposals into the common persistent rollout contract while
  preserving StarVLA checkpoint and preprocessing identities.
- Added persistent full-agent Astra tools for hybrid proposal review and direct
  bounded EEF control.
- Separated persistent model turns, controller decisions, policy calls,
  correction steps, control ACKs, wall time, and token counters.
- Added uncached-work guards so cached context reuse does not falsely exhaust a
  total-token watchdog.

### Evaluation reliability

- Fixed reset/layout identity and rejected broken simulator startup before a
  case could be counted.
- Preserved interrupted and invalid attempts with explicit reasons and costs.
- Required pinned StarVLA identity before simulator reset.
- Added campaign completion status, supervisor receipts, runtime identity, and
  live dashboards that do not display pending work as zero success.
- Added a development-only QwenPI fixed-15 cadence ablation; formal baseline
  cadence remains protected from this override.

### Reproducibility

- Recorded the selected Codex CLI executable and digest.
- Created independently verified source/dependency snapshots and recursive file
  manifests for UnityPolicy, GPT-as-Policy, StarVLA, RoboDojo, and initialized
  submodules.
- Recorded remaining external asset and environment boundaries instead of
  claiming a stronger freeze than the evidence supports.
- Cross-checked native receipts against the GPT-as-Policy and QwenPI_v3
  workstream handoffs.

## Retained development evidence

All rows below use `build_tower`, standard variant, simulator seed 0, layout
reset seed 5. They are off-panel development evidence and are excluded from the
formal 75-episode comparison.

| Method / attempt | Native terminal | Score | Steps | Policy calls | GPT correction steps | Episode wall time |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| QwenPI_v3, 16-step baseline | failure/timeout | 10 | 1050 | 66 | 0 | 14.5 min |
| Astra + QwenPI_v3 | success | 100 | 761 | 52 | 0 | 25.4 min |
| QwenPI_v3 fixed-15 auxiliary ablation | failure/timeout | 0 | 1050 | 70 | 0 | 10.4 min |
| Astra Direct | running at snapshot time | — | incomplete | 0 | direct control | incomplete |

The hybrid success is a real native terminal success, but it is not yet a
causal demonstration that GPT correction improved QwenPI_v3. The run recorded
zero correction steps, and the hybrid dynamically executed mostly 15-step
student prefixes while the baseline executed 16-step prefixes. The auxiliary
fixed-15 baseline also failed, but its initial pixels and proposals were not
bitwise identical. One episode per variant is not a success-rate estimate.

Detailed receipts, digests, timing, token accounting, visual audit, and

behavior and result semantics are reviewed at contract boundaries rather than
through inheritance from a particular upstream project.

## External and local-only artifacts

This repository does not vendor model checkpoints, RoboDojo assets, simulation
videos, full trajectories, credentials, or cluster-specific environments. The
development machine retains raw runs under `runs/`, but
those paths are evidence locations for authorized operators, not public
dependencies.

Reproduction requires independently supplying and recording:

- RoboDojo and initialized simulator submodules/assets;
- StarVLA/QwenPI_v3 source, checkpoint, and normalization configuration;
- GPT-as-Policy tool dependencies used by the persistent rollout;
- an authenticated Codex CLI route exposing the selected Astra model;
- simulator and policy workers with one authoritative connection per episode.

Never commit credentials, checkpoints, datasets, raw traces, or local absolute
paths into reusable configuration.
